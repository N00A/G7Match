28 - La rama de integracion (Develop) es la que va a tener la integracion continua con git actions, el git actions tiene un conjunto de instrucciones que son: hacer el build, ejecutar el test, ejecutar sonar, esto es el script de integracion continua, el script lo que hace es que cuando ya aprobaron el pull request a Develop intenta hacer el build, para poder hacer el build tiene que ejecutar las pruebas unitarias, si pasaron entonces se crea la unidad desplegable, si se pudo crear la unidad desplegable entonces se ejecuta el sonar tomando el codigo que esta en Develop y revisa estaticamente el codigo y genera el reporte en la nube

33 - Integración continua (CI): es el proceso de que cada vez que alguien sube cambios al código (push), el sistema automáticamente construye el proyecto, ejecuta pruebas y valida quetodo siga funcionando bien. Ejemplo: usar GitHub Actions o Jenkins para compilar y correr tests al hacer un commit.

34 - Despliegue continuo (CD): es llevar automáticamente el código validado a un entorno de ejecución (por ejemplo, staging o producción). Así, cuando la aplicación pasa las pruebas, se publica sin intervención manual. Ejemplo: que Spring Boot se despliegue solo en un servidor como Heroku, AWS o Docker.

35 - Análisis estático del código: es revisar el código sin ejecutarlo, usando herramientas que detectan errores, malas prácticas, vulnerabilidades o problemas de estilo. Ejemplo: usar SonarQube o Checkstyle para evaluar calidad y seguridad en el código fuente de Java.

36 - la primera practica de calidad de devops es Integración Continua (Continuous Integration - CI)
